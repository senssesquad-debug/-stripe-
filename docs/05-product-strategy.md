# Продукт: стратегия, рост, монетизация, масштабирование

## 1. Главная проблема рынка — покрытие событий
Технически собрать места просто (OSM даёт тысячи объектов). Конкурентное преимущество —
**полнота и достоверность афиши**, а она на Кипре живёт в Instagram и на билетных сайтах без API.
Поэтому рост покрытия — это работа с поставщиками данных, а не парсинг:

1. **Кабинет организатора (реализовано: «Добавить событие» + модерация).** Следующий шаг —
   верифицированные организаторы публикуют без модерации, видят просмотры/сохранения/клики на билеты.
2. **Партнёрства с билетными платформами** (SoldOut Ticketbox, Ticketbox, More.com): фид в обмен на
   трафик и партнёрскую комиссию с билетов. Это главный рычаг покрытия концертов и вечеринок.
3. **Муниципалитеты и культурные организации**: им выгодно бесплатное распространение. Просим
   JSON-LD/iCal-фид (у многих сайты на WordPress — плагин календаря даёт фид «из коробки»).
4. **Сообщество**: «Сообщить об ошибке/отмене» (реализовано), в будущем — «Предложить событие» от
   пользователей с проверкой.

## 2. Ежедневная полезность (retention)
- **Практические места** — аптеки, банкоматы, заправки, EV-зарядки с честным «открыто/закрыто сейчас»
  (реализовано). Следующее: официальный список **дежурных аптек** (нужен надёжный источник/договор
  с Министерством здравоохранения).
- **Погода + идеи под погоду** («ветрено — не пляж, а музей»).
- **«Сегодня вечером»** как ритуал: короткий дайджест в 17:00 с 1–2 проверенными событиями
  (уведомления с жёсткими лимитами — реализовано).
- **Пляжи**: Blue Flag, вода/ветер, наличие спасателей — источники: Blue Flag Cyprus, open data.

## 3. Умные рекомендации — следующий уровень
Сейчас: интерпретируемая модель (интересы, неявная аффинити по взаимодействиям, расстояние, время
суток, бюджет, возраст, разнообразие). Дальше:
- офлайн-оценка по логам (CTR/save rate), A/B-тест весов;
- коллаборативный сигнал «людям с похожими сохранениями нравится» (обезличенно, k-anonymity);
- контекст: погода, день недели, праздники (календарь PH Кипра уже есть в коде часов работы).
AI не придумывает факты: только интерпретирует запросы и объясняет выдачу шаблонами.

## 5. Международное масштабирование
Архитектура уже готова: страны и города — данные (`packages/core/src/regions.ts` → таблицы
`countries/cities`), часовой пояс берётся из города/события, категории универсальны, локали
добавляются одним файлом строк. Запуск новой страны:
1. добавить страну/города + локаль (например, `pt` для Португалии);
2. включить OSM/Wikidata-источники для кода страны (тот же коннектор);
3. найти 2–3 официальных/билетных источника событий и партнёров;
4. проверить юридические особенности (GDPR одинаков в ЕС; для не-ЕС — локальные законы).
Логичный порядок: Мальта, Греция (язык уже поддержан), Португалия — схожий туристический профиль.

## 6. Метрики
North Star: **число людей, которые за неделю сходили туда, что нашли в passtra** (прокси:
маршрут/билет/«я пошёл»). Плюс: D1/D7/D30 retention, доля событий со статусом `confirmed`,
медианная «свежесть» данных, число открытых конфликтов, время модерации заявки организатора.

## 7. Чего не делать
Не наращивать функции ради функций; не включать платные фичи раньше ядра; не покупать «серые»
базы и не парсить соцсети; не обещать полноту, которой нет — честная плашка «пока мало событий»
лучше выдуманной афиши.
