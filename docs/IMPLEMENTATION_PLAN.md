## Architecture

```
com.lostfeatures
├── LostFeatures            mod entry: registers everything, wires events
├── config                  LFConfig (all toggles), ConfigEnabledCondition (datapack condition)
├── registry                blocks, items, entities, block entities, sounds, tabs, components, tags
├── block / block.entity    devices, traps, altar, decorative and story blocks
├── entity                  RedDragon, LostGiant, LostIllusioner, KillerBunny, lifecycle
│   └── ai.relationship     data-driven relationship engine
├── item                    quiver, horn, armor, journal, fang blade, compass
├── story                   milestones, saved progress, vanilla boss observer
├── network                 journal sync payload
├── world                   signals, Far Lands density, memory, ecology, structures, events, commands
├── client                  renderers, models, journal screen, situational music (client only)
└── data                    datagen providers (models, recipes, loot)
```

Generators that produce committed resources (re-run after changes):

* `./gradlew runClientData runServerData` — models, recipes, loot tables → `src/generated/resources`
* `python3 tools/datagen/gen_data.py` — tags, worldgen, structures, dimension, relationships, lang
* `python3 tools/assetgen/gen_*.py` — textures, paintings, entity models; `gen_audio.py` — all audio
* `python3 tools/docs/gen_docs.py` — RECIPES.md and ASSETS_AND_AUDIO.md

## Design rules followed

1. Additive only; nothing vanilla replaced (COMPATIBILITY.md).
2. Server-authoritative; clients receive only display data.
3. Every system bounded (caps listed in WORLD_SIMULATION.md §6).
4. Every attack telegraphed; every boss has counterplay.
5. Every drop has a use or is a declared trophy.
6. Disabling a feature stops it but keeps registries so worlds stay loadable.
