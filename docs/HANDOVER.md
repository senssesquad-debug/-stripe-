# passtra — передача проекта разработчику

Документ для того, кто продолжает разработку. Здесь коротко: что это, как устроено, как запустить, как
выкатить, что уже сделано и что делать дальше. Подробности по темам — в остальных файлах `docs/`.

## 1. Что это

passtra — приложение «что происходит вокруг и чем заняться» для Кипра (дальше — другие страны): события,
места и активности рядом, поиск на английском, греческом и русском, план дня, маршруты с пошаговой навигацией,
отзывы. Веб-версия работает сейчас: https://passtra.onrender.com (админка — `/admin/`).

Главные правила проекта (их нельзя нарушать):
- **Никаких выдуманных данных.** Неизвестные часы, цены, даты показываются как неизвестные. AI только понимает
  запрос и пишет описания из подтверждённых фактов (числа сверяются), сам места и события не создаёт.
- **Только легальные источники.** Официальные API и открытые данные. Сайты — только через машиночитаемые
  фиды с учётом robots.txt и условий. Instagram/Facebook не парсить (см. `docs/04-api-keys.md`).
- **Секреты только на сервере.** В репозитории их нет; есть только `.env.example`.
- **Не симулировать** отправку кодов, уведомления и геолокацию. Симуляция навигации — только режим для
  разработчика с красной плашкой.

## 2. Доступы, которые нужно передать

| Что | Где | Как передать |
|---|---|---|
| Код | GitHub `senssesquad-debug/-stripe-`, рабочая ветка `claude/fervent-maxwell-r7hhj0` | Settings → Collaborators → добавить человека. Рекомендуется слить ветку в `main` и дальше работать от `main` |
| Хостинг | Render: сервис `passtra` и база `passtra-db` (Blueprint из `render.yaml`) | Render → Workspace → Members → пригласить, или передать workspace |
| Ключи | Render → сервис `passtra` → Environment | Переносятся вместе с Render. Список и назначение — `docs/04-api-keys.md` и `apps/api/.env.example` |

**Важно про бесплатный Render:** сервис засыпает через 15 минут без запросов; бесплатная база Postgres
**удаляется через 30 дней** после создания (дата видна в Render → `passtra-db`). До этого её нужно перевести
на платный план или перенести данные (см. раздел 6).

## 3. Устройство

Монорепозиторий pnpm (Node 22, pnpm 10, TypeScript везде):

| Путь | Что |
|---|---|
| `packages/core` | Вся предметная логика без внешних зависимостей: категории (~115, с тегами OpenStreetMap и словами на 3 языках), разбор запросов, время Кипра, ранжирование и сбалансированная лента, «Чем заняться» (`activities.ts`), план дня (`plan-day.ts`), **навигация** (`navigation.ts`: ведение по маршруту, камера, симуляция) |
| `packages/brand` | Цвета, шрифты, отступы |
| `apps/api` | Fastify API + фоновый воркер: PostGIS, импорт источников (`src/engine/connectors/*`), объединение дублей и конфликты, поиск, лента, план, маршруты, транспорт (GTFS), аккаунты, отзывы и модерация, аватары, уведомления, админ-эндпоинты |
| `apps/admin` | Админ-панель (React/Vite), отдаётся API по `/admin/` |
| `apps/mobile` | Приложение Expo SDK 58 (iOS, Android и веб из одного кода, expo-router) |
| `infra/` | `Dockerfile` (один образ: API + админка + веб), `docker-compose.yml` (локальная база) |
| `docs/` | Исследование, архитектура, UX, ключи, стратегия, тестирование, релиз, отчёты |

Источники данных: OpenStreetMap (ежедневный файл Geofabrik по Кипру), Wikidata + Wikimedia Commons,
visitcyprus.com (события), расписания автобусов Motion (GTFS), MET Norway (погода). Опционально: Google Places,
Ticketmaster, Eventbrite. Каждый факт хранит источник и время проверки.

Ключевые файлы для старта:
- `docs/02-architecture.md` — схема БД и движка импорта;
- `apps/api/src/services/discovery.ts` — лента, поиск, рекомендации, «Чем заняться», план дня;
- `apps/api/src/routes/public.ts`, `web.ts` — публичные эндпоинты, маршруты;
- `apps/mobile/src/app/` — экраны (`(tabs)/index.tsx` главная, `navigate.tsx` навигация, `plan.tsx` план);
- `apps/mobile/src/lib/navigation-session.ts` — GPS/симуляция + перестроение + камера.

## 4. Локальный запуск

```bash
# База: PostgreSQL 15+ с PostGIS и pg_trgm (или Docker):
docker compose -f infra/docker-compose.yml up -d db

pnpm install
cp apps/api/.env.example apps/api/.env
#   в apps/api/.env задать: AUTH_JWT_SECRET (любая строка ≥ 32 символов), DEV_SHOW_CODES=true, NODE_ENV=development
pnpm db:migrate

# Данные (без ключей):
pnpm --filter @passtra/api ingest osm_cy              # места: файл Geofabrik по Кипру
pnpm --filter @passtra/api ingest visitcyprus_events  # события
pnpm --filter @passtra/api ingest wikidata_cy         # музеи, памятники, фото

pnpm dev:api        # API на http://localhost:8080 (с RUN_WORKER=true импорт и напоминания идут сами)

# Приложение:
cd apps/mobile && cp .env.example .env && npx expo start          # телефон/эмулятор/веб
# или веб-сборка, которую раздаёт сам API:
cd apps/mobile && EXPO_PUBLIC_API_URL=same-origin npx expo export --platform web --output-dir dist
#   и APP_STATIC_DIR=<путь>/apps/mobile/dist в apps/api/.env, перезапустить API
```

Админ: зарегистрироваться в приложении, подтвердить e-mail кодом (локально код показывается на экране при
`DEV_SHOW_CODES=true`), добавить этот e-mail в `ADMIN_EMAILS` и зайти на `/admin/`.

## 5. Тесты

```bash
pnpm typecheck                         # все пакеты
pnpm --filter @passtra/core test       # ядро: ~320 тестов (в т.ч. навигация и симуляция)
pnpm --filter @passtra/api test        # API: ~160 тестов на настоящей Postgres/PostGIS
                                       # (нужна база; адрес админ-подключения TEST_DATABASE_ADMIN_URL,
                                       #  по умолчанию postgres://passtra:passtra@localhost:5432/postgres)
cd apps/mobile && npx expo lint        # строгий линтер React (в старом коде ~23 замечания, не влияют на работу)
```

Браузерные сценарии (Playwright, против локального сервера с веб-сборкой на :8080):
`node apps/mobile/e2e/navigation.cjs` (14 сценариев навигации на симуляции),
`node apps/mobile/e2e/what-to-do.cjs`, `node scripts/e2e-web-smoke.mjs`.
GitHub Actions (`.github/workflows/ci.yml`) гоняет типы, тесты ядра и API, сборки — на каждый push.

Симуляция навигации в приложении: dev-сборка, или `EXPO_PUBLIC_DEV_TOOLS=true`, или `?devtools=1` в адресе
веб-версии → в панели маршрута появляются кнопки сценариев.

## 6. Выкладка

Render, Blueprint `render.yaml`: один Docker-сервис (`infra/Dockerfile`) + база. Деплой — автоматически при
push в ветку из `render.yaml` (`branch:`). Коммиты, меняющие только `docs/`, `*.md`, тесты и CI, сборку не
запускают (`buildFilter`) — бесплатный план даёт 500 минут сборки в месяц.

- Миграции применяются при старте сервера (`apps/api/migrations/*.sql`, по порядку).
- Импорт идёт внутри процесса API (`RUN_WORKER=true`), порциями по 8 минут; после деплоя прерванный импорт
  продолжается сразу. Состояние источников: `GET /v1/status`; покрытие базы по категориям: `GET /v1/coverage`.
- Перенос на другой хостинг: тот же образ `infra/Dockerfile`, переменные из `apps/api/.env.example`,
  PostgreSQL с PostGIS. Данные можно перенести `pg_dump`/`pg_restore` или просто дать импорту заполнить
  новую базу заново (около часа).

## 7. Состояние на 9 ноября 2026

Сделано и работает (подробности — отчёты `docs/release/test-report.html` и
`docs/release/navigation-activities-report.html`):
- поиск на 3 языках с опечатками, синонимами, автодополнением, расширением радиуса;
- карточки мест и событий, часы работы на неделю с праздниками Кипра, фото (Wikimedia; Google — с ключом);
- маршруты: пешком, велосипед/самокат, авто, общественный транспорт по официальным расписаниям;
  **пошаговая навигация** с режимами камеры, перестроением, симуляцией для тестов;
- план дня (варианты, правка, сохранение, ссылка) — с разнообразием занятий, без перекоса в кафе и бары;
- вкладка событий, календарь; «Чем заняться сегодня?» (40 занятий, фильтры по времени и характеру);
- аккаунты (e-mail/телефон с настоящими кодами), отзывы с модерацией, аватары, проверка адресов,
  уведомления (Web Push, Expo Push), «Мои события» с напоминаниями, админка с модерацией.

База на сервере: ~15 000 реальных мест, из них еда ~29%, активный отдых ~350, спорт ~680, природа ~970,
культура ~1 090; с фото ~110, с часами ~2 100. Событий мало (17) — источников событий без ключей почти нет.

Проверено автоматически: ~480 тестов + 48 браузерных сценариев. **Не проверено на реальных iPhone/Android**
(навигация в движении, фоновая работа, push на телефонах) — нужны сборки EAS и аккаунты разработчика.

## 8. Что делать дальше (по приоритету)

1. **Ключи** (без них часть функций выключена — интерфейс честно это говорит), см. `docs/04-api-keys.md`:
   - `RESEND_API_KEY` + домен — без него нельзя подтвердить e-mail, а значит нельзя оставлять отзывы и войти в админку;
   - `GOOGLE_MAPS_API_KEY` (Places API New + Geocoding) — фото, часы, рейтинги, точные адреса;
   - `ANTHROPIC_API_KEY` — AI-понимание запросов, описания, модерация;
   - Twilio (SMS), Ticketmaster, Eventbrite — по желанию.
2. **Хостинг**: платная база до истечения 30 дней; платный инстанс (или пинг `/v1/health`), чтобы сервер
   не засыпал — иначе импорт, напоминания и проверки адресов идут только пока кто-то пользуется сайтом.
3. **Сборки iOS/Android** (EAS) и проверка навигации на телефонах: Apple Developer, Google Play Console,
   Expo (`docs/release/release-checklist.md`).
4. **Данные об активностях**: подключить Viator Partner API (бесплатный базовый доступ) для экскурсий,
   морских прогулок, сафари; категории без объектов — `GET /v1/coverage`.
5. **События**: подключить больше легальных источников (Ticketmaster, Eventbrite-организаторы, партнёрства
   с площадками; Instagram/Facebook — только через Meta Graph API, см. `docs/04-api-keys.md`).
6. Технический долг: 23 замечания строгого линтера React в старых компонентах; голосовые подсказки в
   навигации; живые позиции автобусов (GTFS-Realtime) не подключены.
